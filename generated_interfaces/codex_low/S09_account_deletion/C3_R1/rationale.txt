**Q1 — Layout and controls.** The screen uses a fixed phone frame with a compact header, an account profile card, then three groups: shopping, preferences, and account and support. Each row has an icon, a short description, and a tap target. I kept editable name and email fields on the Personal details screen so the main settings screen stays easy to scan. Notification and dark appearance switches show their current state; order updates and new arrivals start on, while offers start off. Those are prototype defaults, not required choices. Sign out and account deletion have separate screens because they need more context than a single row can provide.

**Q2 — Application context.** The retail context led to prominent orders, saved items, addresses, and payment settings. Remote account storage and cross-device synchronization led to profile, security, and Privacy & data entries, including data download and account deletion paths. Google Play’s user data context guided the visible privacy and legal labels and the explanation of what account data is stored. I did not add network or policy details to the main list because they are more useful where a user manages data. No specific manifest value was provided that called for a different layout.

**Q3 — Design priorities.** I prioritized finding a setting quickly within the limited phone height. Grouping and short supporting labels make the choices understandable without filling the screen with forms. A tap opens the relevant detail view for editing or explanation. The main trade-off is that some actions take an extra tap, but the account overview remains compact and scannable.
