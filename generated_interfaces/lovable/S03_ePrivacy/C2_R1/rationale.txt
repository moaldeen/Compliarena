Design Rationale Q1 — Structural elements & defaults Layout (top → bottom): Status bar + notch (device realism) Progress indicator ("Step 3 of 3") — anchors this as the final pre-home step Header: small "Your data, your call" pill + serif headline + one-line subcopy Three preference rows (Analytics / Personalization / Personalized ads), each a tappable card with icon, title, one-line description, and a toggle Action stack: primary "Accept all", then a 2-column "Reject all" / "Save choices", then a tiny "GDPR · Privacy policy" line Why these elements: Three categories, not one blanket switch. EU consent must be granular and purpose-specific. Collapsing them would be dark-pattern territory. Three equally-weighted actions. "Reject all" is given the same visual prominence as "Accept all" (GDPR/EDPB guidance: rejecting must be as easy as accepting). "Save choices" exists so granular toggling is meaningful. No email field, no account form, no marketing checkboxes. Onboarding already collected language/preferences; adding inputs here would dilute the single decision the screen asks for. Progress dots + "Step 3 of 3" instead of a back arrow — the user is committing, not branching. Defaults: Analytics: on — lowest-risk, product-quality signal, but still user-revocable. Personalization: on — core to a shopping app's value; toggleable. Personalized ads / advertising ID: off — GDPR requires opt-in, not opt-out, for ad tracking. Pre-checking it would be non-compliant. Q2 — How the manifest shaped the UI The manifest declared: Android e-commerce app, EU jurisdiction, analytics + advertising SDKs, advertising IDs, retargeting, third-party ad/measurement partners. That directly produced: The screen itself exists because EU + tracking IDs + third-party ad partners = mandatory consent surface before any SDK fires. Granular toggles map 1:1 to the SDK categories named in the manifest (analytics, personalization, ads) rather than a single "I agree." Ads default OFF specifically because the manifest mentions advertising identifiers and retargeting — GDPR treats those as requiring explicit opt-in. "Reject all" equal in weight to "Accept all" — required when third-party ad partners are involved. "GDPR compliant · Privacy policy" footer and "change anytime in Settings" copy address the manifest's third-party sharing disclosure obligation. What I deliberately did not change: the standard mobile onboarding chrome (status bar, progress dots, single-screen vertical stack, home indicator). The manifest describes data practices, not a novel form factor — inventing a non-standard layout would hurt comprehension on the exact step where comprehension is legally required. Q3 — Intent & trade-offs Priorities, in order: Informed consent over conversion. The screen could have been a one-tap "Continue" with buried settings — that converts better but fails GDPR and erodes trust. I chose visible, equal-weight choices. One decision, one screen. No scrolling, no tabs, no expandable accordions. Everything fits in the device frame so the user sees the full set of choices before acting — no hidden options. Fast path preserved. Users who don't care still get a single prominent "Accept all" CTA. The granular path is one tap away, not the only path. Trade-offs I accepted: Short descriptions vs. full legal text. One line per category keeps the screen scannable; the "Privacy policy" link carries the full disclosure. Comprehension > completeness on this surface. Three buttons instead of one. Slightly busier footer, but legally and ethically necessary — a single "Continue" with toggles above is the dark pattern this screen exists to avoid. Defaults are opinionated, not neutral. True neutrality (all off) would tank product analytics; all-on would be non-compliant. The split (analytics/personalization on, ads off) reflects both legal posture and user benefit. Editorial serif headline + warm terracotta instead of the generic blue-cookie-banner aesthetic — consent doesn't have to feel like a tax; matching the shopping brand voice makes the moment feel like part of the experience, not an interruption before it.
